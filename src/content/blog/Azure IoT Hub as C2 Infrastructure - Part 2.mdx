## The Challenge: Remote PowerShell in a Cloud-First World

Traditional PowerShell execution has always been a local affair. You need to be physically present at a machine, or use Remote PowerShell (WinRM), which comes with its own set of security concerns, firewall complications, and scalability limitations. In today's cloud-native, distributed infrastructure landscape, this approach simply doesn't scale.

**Enter Azure IoT Hub**—Microsoft's robust platform for managing millions of devices at scale. What if we could leverage this battle-tested infrastructure to execute PowerShell scripts remotely, with the same reliability and security that powers IoT deployments worldwide?

That's exactly what IoTPowerShellAgent accomplishes. It's not just a PowerShell executor—it's a complete transformation of how we think about remote Windows automation.

## What is IoTPowerShellAgent?

IoTPowerShellAgent is a **Windows Service** that acts as a bridge between Azure IoT Hub and PowerShell execution. Think of it as a secure, scalable, and intelligent agent that:

- **Listens** for PowerShell script execution requests via Azure IoT Hub direct methods
- **Executes** scripts with full system privileges (running as `NT AUTHORITY\SYSTEM`)
- **Streams** all output types (Verbose, Debug, Warning, Error, Information, Progress) in real-time
- **Converts** complex PowerShell objects into structured JSON for API integration
- **Monitors** system performance and provides telemetry back to the cloud
- **Logs** everything comprehensively for audit and troubleshooting

### The Architecture: Built for Scale and Reliability

The project follows a clean, modular architecture that separates concerns beautifully:

```txt
IoTPowerShellAgent/
├── Core/          # Domain models and core services
├── PowerShell/    # PowerShell host and executor
├── IoT/           # Azure IoT Hub integration
├── Services/      # Windows Service implementation
└── Utilities/     # JSON conversion, process management, etc.
```

This architecture ensures that each component has a single, well-defined responsibility, making the system maintainable, testable, and extensible.

## The Magic: JSON Conversion Engine

One of the most fascinating aspects of IoTPowerShellAgent is its **embedded JSON conversion module**. This isn't your run-of-the-mill JSON serialization—it's a sophisticated engine specifically designed to handle PowerShell's unique object model.

### The Conversion Challenge

PowerShell objects are complex beasts. They can be:

- **PSObjects** with dynamic properties
- **Hashtables** and **Dictionaries**
- **Arrays** and **Collections**
- **Custom objects** with nested structures
- **Enums** that need special handling
- **DateTime** objects requiring ISO 8601 formatting

Standard JSON serialization libraries often fail to capture the full richness of PowerShell objects, losing type information, nested properties, and the dynamic nature that makes PowerShell so powerful.

### The Solution: Embedded Conversion Module

IoTPowerShellAgent includes an embedded JSON conversion module (formerly the standalone `powershellruntimeextension` project) that provides:

#### 1. **Intelligent Type Handling**

The conversion engine understands PowerShell's type system deeply. It can:

- Preserve PSObject properties and metadata
- Handle nested objects recursively
- Convert enums to strings or integers based on context
- Format dates in ISO 8601 format automatically
- Manage depth limits to prevent infinite recursion

#### 2. **PowerShell-Specific Features**

```csharp
// The engine handles complex PowerShell scenarios:
- PSCustomObject serialization
- Hashtable conversion with proper key handling
- Array processing with type preservation
- Error record serialization with full stack traces
```

#### 3. **Configurable Output**

The conversion is highly configurable:

- **Max Depth Control**: Prevents stack overflow on deeply nested objects
- **Enum Handling**: Convert enums to strings for readability or integers for compactness
- **Compression**: Generate compact JSON or pretty-printed, indented output
- **String Escaping**: Proper handling of special characters

### Real-World Example: From PowerShell to API

Here's how the conversion process works in practice:

**PowerShell Script:**

```powershell
Get-Process | Select-Object -First 5 Name, CPU, WorkingSet
```

**Traditional JSON Output (Limited):**

```json
{
  "Name": "chrome",
  "CPU": 123.45,
  "WorkingSet": 12345678
}
```

**IoTPowerShellAgent JSON Output (Rich):**

```json
{
  "Success": true,
  "Output": "[{\"Name\":\"chrome\",\"CPU\":123.45,\"WorkingSet\":12345678},...]",
  "RawOutput": [
    {
      "Name": "chrome",
      "CPU": 123.45,
      "WorkingSet": 12345678,
      "PSComputerName": null,
      "RunspaceId": "..."
    }
  ],
  "ErrorDetails": null
}
```

The conversion preserves not just the data, but the **context** and **metadata** that makes PowerShell objects so powerful.

## The Conversion Process: Under the Hood

Let's dive deeper into how the JSON conversion actually works:

### Step 1: PowerShell Execution

When a script is executed, PowerShell returns objects in its native format—PSObjects, arrays, hashtables, etc.

### Step 2: Object Analysis

The conversion engine analyzes each object:

- Determines the base type (string, number, object, array, etc.)
- Identifies PSObject wrappers and their properties
- Detects nested structures
- Checks for circular references

### Step 3: Recursive Processing

The engine processes objects recursively:

```csharp
ProcessValue(object obj, int depth, ConvertToJsonContext context)
{
    // Handle nulls and AutomationNull
    // Unwrap PSObjects
    // Process dictionaries
    // Process enumerables
    // Handle primitives
    // Process custom objects
    // Add PSObject properties
}
```

### Step 4: JSON Serialization

Finally, the processed object graph is serialized using Newtonsoft.Json with custom settings:

- Type name handling disabled (clean JSON)
- Max depth enforcement
- Enum conversion based on context
- Pretty printing or compression

### Step 5: Result Packaging

The JSON is packaged into a `PowerShellExecutionResult` object that includes:

- Success status
- Formatted output string
- Error details (if any)
- Raw output objects
- Exception information

## Security Considerations

Running as `NT AUTHORITY\SYSTEM` provides maximum script execution capabilities, but requires careful security planning:

### **Best Practices:**

1. **Secure Connection Strings**: Store IoT Hub connection strings securely
2. **Access Control**: Limit script execution permissions through IoT Hub policies
3. **Audit Logging**: Monitor all activity logs for suspicious behavior
4. **Network Security**: Use Azure Private Link for IoT Hub when possible
5. **Script Validation**: Validate scripts before execution when possible
6. **Least Privilege**: Consider running with reduced privileges for specific use cases

## Getting Started

### Prerequisites

- .NET 8.0 SDK or later
- Windows 10/11 or Windows Server 2016+
- Azure IoT Hub account
- PowerShell 5.1 or later

### Quick Start

1. **Clone and Build:**

```bash
git clone <repository>
cd IoTPowerShellAgent/src/IoTPowerShellAgent
dotnet build
```

2. **Configure:**

  ```json
  {
    "IoTHubConnectionString": "HostName=your-iothub.azure-devices.net;...",
    "DeviceId": "your-device-id",
    "ScriptTimeoutSeconds": 300
  }
  ```

3. **Test Locally:**

```bash
dotnet run -- --debug
```

4. **Deploy as Service:**

```bash
IoTPowerShellAgent.exe install
IoTPowerShellAgent.exe start
```

### Execute Your First Script

Via Azure IoT Hub Direct Method:

```json
{
  "methodName": "ExecuteScript",
  "payload": {
    "Script": "Get-Date | ConvertTo-Json",
    "IsInlinePowershell": false
  }
}
```
